# Plot Twist, a challenge randomizer for life-sim runs

Notes from the Saxton Showcase, written for an AI helper as much as for a person. Hand this file to your agent along with `plot-twist.html`, the build itself, and it gets what we learned without having to rebuild it to find out.

- Built: 2026-09-23
- Tags: tool, life-sim, randomizer, challenge, checklist, touch, keyboard, web audio
- Who made it: Amy, our AI helper (an AI, not a person), built it because we asked for it. People decided it should be made and approved putting it on the shelf. In the notes below, "I" is Amy, and a "session" is one of her working runs.
- The build: one self-contained HTML file. Open it in a current browser; it needs no install, no account and no internet. It makes sound with Web Audio, which the browser starts only after your first tap, click or key. Anything it saves (progress, scores or settings) stays in your own browser's localStorage and is never sent anywhere.

## What it is

A single-file browser tool for people who play life-simulation games. Deal (button or Space) spins seven cards and flips them over: a starting budget band, a household setup, a house rule, a career direction as a broad job family, a personality to play, a goal and a twist that lands on a set day. Any card can be locked while the rest re-roll. A difficulty dial (cosy, spicy, chaotic) weights which entries can appear, and every entry carries its own tag. Play this run turns the run into a checklist with a day counter, and the twist stays sealed until its day. Runs save to a history, share as a short code (base-36 seed and dial, then the list version, then a group for each locked card that came from an earlier deal) that deals the exact same run, and download as a 1080x1350 PNG card. All 214 entries (20 to 25 per category, 66 twists) are our own generic writing and can be edited on the My lists screen: add, remove, retag, reset one list or all. History and lists export to and import from a .json file. Sound is synthesized, starts after the first input and has a mute button plus the M key. ?preview=1 deals run after run with the spin and no chrome.

## What we learned building it

Locking and share codes pull against each other. A locked card came from an earlier seed, so one seed cannot reproduce a run once anything is locked. The fix was to give every card its own sub-seed (the run seed mixed with the card's position) and have each card remember the seed and dial it came from. The code is then the run's seed plus one short group per locked-in source, and a plain run's code stays short (S1IY5ZT3-EAXWZ). The list version is a hash of every entry, its tag and its order, so any edit changes it. Undoing an edit or resetting the lists brings the old version back, so default codes work for anyone on default lists. Keeping the logic pure also meant node could chain 2400 random re-rolls and check that the final code still deals the exact run.

## The gotcha

The slot reels stopped a few pixels off their final row, and the error grew with each card (2 px on the first, 8 px on the last in the preview). The first version measured the reel row height while the card back was still display:none and fell back to a guessed 36 px. Measuring after the flip used offsetHeight, which rounds 36.8 px down to 36 and drifts 0.8 px per row over a 12 to 24 row strip. getBoundingClientRect was worse, because it includes the 3D flip transform running on the card. The height from getComputedStyle is unrounded and ignores transforms, and fixed it. A browser check now compares every stopped reel with its final row at desktop, phone and preview sizes (within 0.3 px). A smaller one: the first list-version hash used only the first letter of each tag, and cosy and chaotic both start with c, so retagging between them did not change the version. A node test caught it.
