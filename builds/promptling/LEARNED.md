# Promptling, bite-size lessons for using AI well

Notes from the Saxton Showcase, written for an AI helper as much as for a person. Hand this file to your agent along with `promptling.html`, the build itself, and it gets what we learned without having to rebuild it to find out.

- Built: 2026-09-23
- Tags: learning, game, AI literacy, daily habit, touch, keyboard, web audio
- Who made it: Amy, our AI helper (an AI, not a person), built it because we asked for it. People decided it should be made and approved putting it on the shelf. In the notes below, "I" is Amy, and a "session" is one of her working runs.
- The build: one self-contained HTML file. Open it in a current browser; it needs no install, no account and no internet. It makes sound with Web Audio, which the browser starts only after your first tap, click or key. Anything it saves (progress, scores or settings) stays in your own browser's localStorage and is never sent anywhere.

## What it is

A daily-habit learning app in one offline HTML file. A winding path of 31 nodes across six units (what an AI chat actually is, asking well, checking what it says, staying safe, getting real things done, knowing the limits): 25 lessons plus a review node closing each unit. Lessons are 6 to 8 quick exercises of seven kinds: multiple choice, which prompt is better, spot the made-up part, build the prompt (pick the ingredients a prompt has or lacks), safe or not safe (tap or swipe), put the steps in order, and fix it (choose the best follow-up after a disappointing reply), plus a pick-all-that-apply variant. Right answers get a bright bar, a chime and a one or two sentence reason; wrong answers cost a heart, show the reason and the answer, and return at the end of the lesson. Five hearts refill one per thirty minutes of real time, or all at once through a practice round of questions already seen. XP, a daily goal ring, a day streak counted in calendar days in the player's own time zone, a finish screen with confetti, and a profile with total XP, streak, best streak, lessons done and a confirmed reset. Pip, the mascot, is a teal speech bubble with a star on its head, drawn as inline SVG. No real AI is called; the whole curriculum (169 exercises) is one data block between LESSONS-BEGIN and LESSONS-END markers. ?preview=1 runs a silent 2:1 attract loop with a visible fake finger.

## What we learned building it

Keeping the curriculum as a pure data block made the accuracy rules testable rather than a promise: a ban on any digit in lesson text is a cheap, blunt proxy for no statistics, dates or prices, and it plus a list of product, company and month names runs on every check, with planted defects to prove the scanner bites. Writing the spot-the-made-up-part exercises around a snippet the learner pasted (a flyer, an invitation, a letter) meant the correct answer is checkable inside the exercise itself, so the lessons never had to assert a single fact about the outside world to teach fact-checking. On the layout side, CSS media queries answer to the real viewport, not to a scaled stage: the preview is a 640 by 320 stage scaled into a 600 px iframe, so the phone rules (stacked feedback bar, full-width buttons) fired inside it and the bar covered the answer it was praising, until preview-specific overrides were added.

## The gotcha

The path never scrolled to the player's current lesson, and every automated check still passed, because none of them looked. Only the preview screenshot showed it: the demo tapped a node while the view sat on unit one. The scroll used the node's offsetTop, but each node sits in a position:relative row, so offsetTop was measured from the row (about 12 px) rather than from the path. It now uses the difference of the two bounding rectangles, divided by the preview's scale factor so it also works on the scaled stage. A smaller one in the test itself: after Continue the feedback bar keeps its 'good' class and only loses 'on', so the first preview check counted the home screen as showing the right-answer bar; the check now requires both classes.

## Since then

On 2026-10-18 an AI review session checked every lesson against current practice and changed this copy. The correct answer had been the longest option in 54 of 58 multiple-choice questions and all 23 which-prompt-is-better pairs, so a learner could pass by picking the longest answer; ten wrong options were rewritten as believable misconceptions (for example "two assistants that agree must be right"), and one which-prompt pair now has a long, polite but empty prompt as the wrong answer, with the reason "longer isn't better". The made-up-part exercises now shuffle their sentences, because the invented one had been the last sentence in 6 of the 7. Two explanations were sharpened: written-out reasoning is not always how the assistant really reached its answer, and many AI services set a minimum age. The START tag and the red buttons were recoloured to pass contrast, and the progress bar now reports its value to screen readers. After the changes the original checks were re-run on this copy: test_content.js 103 of 103 and test_ui.js 58 of 58, plus a phone run that finished all 31 lessons and reviews by taps with zero errors and no outside requests.
